# 工作方式与扩展

[返回首页](../README.md) · [配置参考](CONFIGURATION.md)

## 游戏是规则与接话一起推进

`games.py` 注册三个游戏，每个提供 `start`、`opening`、`accepts`、`advance` 和 `hint`。返回的 `Turn` 描述公开规则结果及这一刻可以有的感受。后续可以在同一接口加入新游戏，并在配置页增加选项。

猜数字开局时固定答案，模型的接话输入只包含游戏名和情绪时刻。猜拳开局及每轮结束时选好下一拳，用户出拳后按规则比较。故事接龙保存双方的故事句子，由模型在后台续写，末轮提示收尾。

模型接话与规则结果分别生成，最终游戏消息保留本地规则提示。模型可以得意、不服或佩服，答案、比分和规则由游戏实现控制。

## 只接收明确的游戏输入

自定义 `PlayInputFilter` 只在有效游戏操作、邀请回应或明确“陪我玩”时匹配。游戏处理器优先级为 1000，在消息合并等常规监听器前处理属于游戏的输入，入队后立即停止该条事件。

普通话题、其他插件命令、群里非当前玩家的发言继续原流程。当前群维护一局，WeChat Native 的成员隔离会话 ID 会按真实群 ID 归到同一游戏范围。

## 后台处理与已有插件

游戏输入只更新小量状态并加入对应局的队列。规则、人格化接话、故事生成及发送在后台处理。主动邀玩使用独立任务，普通聊天到来时取消尚未发出的邀请和可中断的接话生成。

人格通过 AstrBot 的会话人格解析接口读取。安装短期共享情绪时，合成事件 ID 以 `proactive:` 开头，复用其表达提示而不作为新的用户刺激。正常游戏输入不会伪装成普通用户聊天。

安装自娱自乐时，可以读取它对当前会话的相处印象，邀玩更偏向聊得来的人。游戏进行中将其下一次活动延后到本局暂歇，降低两边同时搭话的可能。两者仍是独立插件。

游戏结束的公开结果可作为临时 `TextPart` 加入下一次普通对话，让后续聊天记得刚才一起玩的经历。未将游戏答案或未公开出拳加入普通对话。

## 状态与验证范围

数据写入 `data/plugin_data/astrbot_plugin_play_together/play.json`，包含当前游戏、公开消息、必要的游戏秘密和最近结果。状态原子写入，重启后未过期的局可以继续，旧消息不会自动重发。

```shell
python -m unittest discover -s tests -v
```

测试覆盖三种游戏规则、九种猜拳组合、选择性输入、群内玩家区分、连续操作、停止慢生成、原生配置窗口、真实核心加载及热重载。独立运行状态中使用已配置模型进行过猜数字开场与收尾、故事接龙生成预览。

自动邀请与游戏投递通过平台既有主动消息接口。真实微信或其他平台的现场投递需要安装并选择目标后验证，群聊能力与主动推送能力以适配器为准。
